## Findings considered and rejected

- `safeToMarkProcessed` race for `unmatchedLeads`/`alreadyCounted` continue paths: originally reported as a bug, but upon code review these paths intentionally mark the payment as "handled" (to avoid retrying unresolvable cases forever). Not a bug — behavior is correct by design.
- Lucide-react version "suspicious": version 1.17.0 actually exists in the npm registry and is present in the lock file. Not a real issue.
- `src/http/` and `src/routes/` as "dead scaffolding": both are actively wired. `api/` imports `trackingHttpHandlers` from `src/index.ts`, which imports `src/http/handlers.ts`, which calls methods on `TrackingApp` which uses `src/routes/` internally. All layers are live.
- `api/dev/*` endpoints "missing auth": upon reading the files, most call `trackingHttpHandlers.postLead` / `postPaymentsSync` which internally call `requireTrackingSecret`. The two that don't (`test-lead.ts`, `test-payment-sync.ts`) bypass the secret check — see SEC-02 note below.
- Dashboard `as unknown` casts: present but not an immediate regression risk; deferred — not worth a dedicated plan right now.
- God component `dashboard.tsx` (2,688 lines): real tech debt, deferred to a dedicated UX sprint; not blocking correctness.
- Build tools in `dependencies` vs `devDependencies`: low risk on Vercel (build env installs all deps); deferred as cosmetic.

### Note on `api/dev/test-lead.ts` and `api/dev/test-payment-sync.ts`

These two files bypass secret auth. They accept any POST and trigger real lead/payment flows with demo data. In production they should be behind the tracking secret or removed. Not planned here because the risk is bounded (demo data, not arbitrary input), but worth addressing before a public URL is shared.

> **Update (2026-06-17):** this is now **plan 013** — `test-payment-sync.ts` triggers the
> *real* payment sync (a backdoor around the `CRON_SECRET`-protected cron), and
> `bootstrap-check.ts` (also unauthenticated) leaks internals. Worth doing now, not deferring.

### Findings considered and rejected — 2026-06-17 follow-up pass

- **`date-ranges.ts:78` "timezone off-by-one"**: false. The `new Date(year, month, 1)` is built
  in local time but only formatted to month+year via `Intl` — local construct + local format is
  self-consistent. No bug.
- **Cron auth "User-Agent spoofable" (SEC-05)**: false. `isAuthorizedCronRequest` **fails closed**
  when `CRON_SECRET` is unset (`api/cron/payments-sync.ts:61-64`). Only the README prose is stale
  (it still describes a User-Agent fallback that the code does not implement).
- **Dentalink webhook "has no auth"**: false. `postDentalinkAppointment` calls
  `requireTrackingSecret` (`src/http/handlers.ts:58`). The real gap is idempotency, not auth →
  reframed as plan 014.
- **lucide-react / radix-ui version anomalies**: real published versions in the lockfile
  (`lucide-react@1.17.0`, `radix-ui@1.5.0`). Not issues (consistent with the prior pass's note).
- **"No tests" / "No CI" / "unused recharts/radix/lucide"**: all wrong — 11 test files exist,
  `.github/workflows/ci.yml` runs check+test+build, and the React app in `src/components/**`
  uses those libraries heavily.
- **Silent memory fallback (`state/config.ts:30`)**: deliberate, documented tradeoff from plan
  004 (keep the dashboard functional without Redis). Not a new bug; optional hardening would be
  to fail loud on the cron path only — deferred.
- **`api/dev/test-patient-treatments.ts` unauthenticated**: returns hardcoded **demo** data via a
  fresh `InMemoryStateStore` — no real PII. Folded into plan 013 for consistency, but low risk.
